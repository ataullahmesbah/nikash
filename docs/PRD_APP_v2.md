## ৩. মূল নিয়ম (ব্যবসায়িক যুক্তি)

### ৩.১ আংশিক পেমেন্ট ও বাকি
- চালান পোস্ট হলে `due = total - paid`
- পরে পেমেন্ট নিলে → `payments` + `payment_allocations` → ট্রিগার চালানের `paid`/`due` বাড়ায়/কমায়
- `v_receivables` / `v_payables` → `party_due_summary()` পার্টিভিত্তিক যোগফল দেয়

### ৩.২ পোস্ট করা বিল সংশোধন (Tally-স্টাইল)
```
পোস্টেড চালান → [এডিট] → কারণ লিখুন
   → unpost_sale(id, reason)
       • স্টক মুভমেন্ট উল্টে দেয়
       • payment_allocations মুছে দেয়
       • status = 'draft', edit_count++
       • entity_audit_log-এ লেখা হয়
   → /sales/new?editId=<id> এ খুলে যায়
   → সংশোধন করে আবার পোস্ট
```
মাস বন্ধ (month-close) হয়ে থাকলে আনপোস্ট আটকে যায়।

### ৩.৩ ডিলিট
| জিনিস | লেনদেন নেই | লেনদেন আছে |
|---|---|---|
| পার্টি | `deleted_at` বসে (সফট ডিলিট) | `is_active = false` → "নিষ্ক্রিয়" |
| পণ্য | `deleted_at` বসে | `is_archived = true` → "আর্কাইভড" |
| ড্রাফট চালান | সারি মুছে যায় | প্রযোজ্য নয় (পোস্টেড ডিলিট হয় না, void হয়) |

**অনুমতি:** আনপোস্ট ও ডিলিট শুধু মালিক/ম্যানেজার — DB ফাংশনের ভেতরেই
`has_role(['owner','manager'])` চেক আছে, UI-এর গার্ডের উপর ভরসা করা হয়নি।

### ৩.৪ অফলাইন
- সব লেখা প্রথমে লোকাল SQLite `sync_queue`-এ
- ক্লায়েন্টেই UUID তৈরি হয় → একই সারি দুইবার যায় না
- `enqueueWriteAndSync()` সেভের পর পুশের জন্য সর্বোচ্চ ৩ সেকেন্ড অপেক্ষা করে,
  তাই তালিকায় ফিরলেই নতুন এন্ট্রি দেখা যায়

### ৩.৫ রিয়েল-টাইম
`lib/realtime.ts` — Supabase `postgres_changes`:
- `companies` (নিজের সারি) → ব্লক/মেয়াদ বদলালে সাথে সাথে
- `notices` → নতুন নোটিশ
- `notifications` → ঘণ্টার ব্যাজ

> ⚠️ Supabase ড্যাশবোর্ড → Database → Replication-এ `notices`, `companies`,
> `users`, `notifications` টেবিলের জন্য realtime চালু করতে হবে।
