# ভাগ ১ — পরিচিতি ও কাঠামো

## ১. সংক্ষিপ্ত পরিচিতি

### ১.১ সমস্যা

বাংলাদেশের মুদি সরবরাহ শৃঙ্খলের তিনটি স্তর — সরবরাহকারী, পরিবেশক (গুদাম) এবং খুচরা দোকান — সবাই একই সমস্যায় ভোগে:

- স্টক, বাকি ও খরচ আলাদা খাতায় থাকে, তাই **আসল লাভ কখনো বের হয় না**
- কার কাছে কত বাকি, কত দিনের পুরনো — মনে থাকে না
- এক পণ্যের একাধিক মাপ ও একাধিক ইউনিট (পিস, প্যাক, কার্টন, বস্তা) থাকায় স্টক মেলে না
- উপরের ও নিচের পক্ষের হিসাব কখনো মেলে না — "আমি ১০ কার্টন দিয়েছি" বনাম "আমি ৯ কার্টন পেয়েছি"

### ১.২ সমাধান

একটি offline-first Android অ্যাপ যা **সরবরাহ শৃঙ্খলের তিনটি স্তরই ব্যবহার করতে পারবে**। প্রতিটি লেনদেন একবার এন্ট্রি দিলেই স্টক, বাকি ও লাভ — তিনটিই একসাথে হালনাগাদ হয়।

বাড়তি সুবিধা: দুই পক্ষই যদি Nikash ব্যবহার করে, তারা পরস্পরকে যুক্ত করে **ডিজিটাল চালান** পাঠাতে পারবে — তখন হিসাবের গরমিল প্রায় শূন্যে নেমে আসবে।

### ১.৩ লক্ষ্য

| লক্ষ্য | পরিমাপ |
|---|---|
| দৈনিক হিসাব মেলানোর সময় | ২ ঘণ্টা → ১৫ মিনিট |
| স্টকের গরমিল | ৫% → ১%-এর নিচে |
| নিট লাভ জানা | প্রতিদিন স্বয়ংক্রিয় |
| প্রথম বছরে গ্রাহক | ২০-৫০ ব্যবসা |

## ২. সরবরাহ শৃঙ্খল ও তিন ধরনের ব্যবহারকারী

```
  উৎপাদক / আমদানিকারক
            │
            ▼
   ┌─────────────────┐
   │  VENDOR         │  Nikash ব্যবহারকারী — ধরন ১
   │  (সরবরাহকারী)   │  বড় লটে বিক্রি
   └────────┬────────┘
            │  বিক্রি
            ▼
   ┌─────────────────┐
   │  WAREHOUSE      │  Nikash ব্যবহারকারী — ধরন ২
   │  (পরিবেশক)      │  গাড়ি, রুট, ডেলিভারি
   └────────┬────────┘
            │  বিক্রি
            ▼
   ┌─────────────────┐
   │  SHOP           │  Nikash ব্যবহারকারী — ধরন ৩
   │  (খুচরা দোকান)  │  POS, খুচরা বিক্রি
   └────────┬────────┘
            │  বিক্রি
            ▼
     সাধারণ ক্রেতা
```

**মূল স্থাপত্য সিদ্ধান্ত:** তিনটি আলাদা অ্যাপ নয়, **একটি অ্যাপ**। কারণ তিনজনই কাঠামোগতভাবে একই কাজ করে — উপরের পক্ষ থেকে কেনে, স্টকে রাখে, নিচের পক্ষে বেচে। শুধু নাম, কিছু ফিচার ও ডিফল্ট সেটিংস বদলায়।

নিবন্ধনের সময় ব্যবসার ধরন বাছাই হবে: `company.business_type = vendor | warehouse | shop`

## ৩. ব্যবসার ধরন অনুযায়ী পার্থক্য

### ৩.১ পরিভাষার মানচিত্র

ডেটাবেসে সবসময় নিরপেক্ষ শব্দ থাকবে (`supplier` / `customer`), শুধু পর্দায় লেখা বদলাবে।

| ডেটাবেসে | Vendor অ্যাপে | Warehouse অ্যাপে | Shop অ্যাপে |
|---|---|---|---|
| supplier | উৎপাদক / মিল | সরবরাহকারী | ডিলার / গুদাম |
| customer | গুদাম / ডিলার | দোকান | ক্রেতা |
| purchase | ক্রয় / আমদানি | ক্রয় | মাল তোলা |
| sale | সরবরাহ | বিক্রয় | বিক্রয় |
| location | কারখানা / গুদাম | গুদাম | দোকান |

| ফিচার | Vendor | Warehouse | Shop |

| ইনভেন্টরি ও স্টক লেজার | ✓ | ✓ | ✓ |
| ক্রয় ও বিক্রয় | ✓ | ✓ | ✓ |
| বাকি ও পেমেন্ট | ✓ | ✓ | ✓ |
| খরচ ব্যবস্থাপনা | ✓ | ✓ | ✓ |
| রিপোর্ট ও ড্যাশবোর্ড | ✓ | ✓ | ✓ |
| **গাড়ি ও ট্রিপ খরচ** | ঐচ্ছিক | ✓ ডিফল্ট | ✗ |

ডিফল্ট সেটিংস নিবন্ধনের সময় বসে যাবে, ক্লায়েন্ট পরে সেটিংস থেকে বদলাতে পারবে।

### ৩.৩ Shop-এর জন্য POS মোড

খুচরা দোকানের চাহিদা আলাদা — দ্রুততা সবচেয়ে জরুরি।

- বড় বোতাম, বারকোড স্ক্যানে সরাসরি কার্টে যোগ
- ক্রেতার নাম না দিলেও চলবে ("নগদ ক্রেতা")
- টাকা দেওয়া-ফেরতের হিসাব স্বয়ংক্রিয়
- শিফট খোলা/বন্ধ — শুরুতে ড্রয়ারে কত ছিল, শেষে কত থাকার কথা, আসলে কত আছে
- বাকিতে বিক্রি করলে ক্রেতার নাম ও ফোন লাগবে

## ৪. সংযুক্ত অ্যাকাউন্ট (Connected Business)

Nikash-এর সবচেয়ে শক্তিশালী ফিচার। দুই পক্ষই Nikash ব্যবহার করলে তাদের হিসাব সরাসরি যুক্ত হবে।

### ৪.১ কীভাবে কাজ করবে

প্রতিটি কোম্পানির একটি অনন্য পরিচয় থাকবে: **`NK-4821`**

1. গুদাম তার দোকানের Nikash ID বা ফোন নম্বর দিয়ে সংযোগের অনুরোধ পাঠাবে
2. দোকান অ্যাপে অনুরোধ দেখবে, গ্রহণ বা বাতিল করবে
3. সংযুক্ত হলে গুদাম বিক্রয় Post করার সাথে সাথে দোকানের অ্যাপে **"আগত চালান"** হিসেবে দেখাবে
4. দোকান চালান দেখে **গ্রহণ** করবে → তার অ্যাপে স্বয়ংক্রিয়ভাবে ক্রয় এন্ট্রি, স্টক বৃদ্ধি ও দেনা তৈরি হবে
5. পরিমাণে গরমিল থাকলে দোকান **আপত্তি** জানাতে পারবে, গুদাম সংশোধন করবে

### ৪.২ কেন এটা গুরুত্বপূর্ণ

- দুই পক্ষের বাকির হিসাব **সবসময় মিলবে**
- দোকানকে হাতে এন্ট্রি দিতে হবে না — ভুলের সুযোগ নেই
- বিরোধ হলে ডিজিটাল প্রমাণ থাকবে
- গুদাম তার দোকানদারদের Nikash ব্যবহারে উৎসাহ দেবে — আপনার গ্রাহক নিজে থেকেই বাড়বে

### ৪.৩ নিয়মাবলি

- সংযোগ সম্পূর্ণ **ঐচ্ছিক**। সংযোগ না থাকলেও অ্যাপের সব কাজ আগের মতোই চলবে।
- কেউ কারও ভেতরের ডেটা দেখতে পাবে না — শুধু নিজেদের মধ্যকার লেনদেন, বাকি ও চালান
- যেকোনো পক্ষ যেকোনো সময় সংযোগ বিচ্ছিন্ন করতে পারবে; পুরনো লেনদেন থেকে যাবে
- গ্রহণ না করা চালান ৭ দিন পর স্বয়ংক্রিয়ভাবে বাতিল হবে, প্রেরককে জানানো হবে

# ভাগ ৩ — ড্যাশবোর্ড ও অ্যানালিটিক্স

## ৯. ড্যাশবোর্ড

ড্যাশবোর্ড ব্যবসার ধরন ও ভূমিকা অনুযায়ী বদলাবে। উদ্দেশ্য একটাই — **মালিক সকালে অ্যাপ খুলে ১০ সেকেন্ডে ব্যবসার অবস্থা বুঝে ফেলবে।**

### ৯.১ উপরের KPI কার্ড

| কার্ড | হিসাব | সাথে থাকবে |
|---|---|---|
| আজকের বিক্রি | আজকের মোট বিক্রয় | গতকালের তুলনায় ↑↓ % |
| আজকের আদায় | আজ কত টাকা এসেছে | লক্ষ্যের কত % |
| হাতে ক্যাশ | আদায় − পরিশোধ − খরচ | — |
| মোট পাওনা | ক্রেতাদের কাছে | ৬০+ দিনের অংশ লাল |
| মোট দেনা | সরবরাহকারীদের কাছে | শীঘ্রই শোধের তারিখ |
| স্টকের মূল্য | ক্রয়মূল্যে | গত মাসের তুলনা |

কার্ডে ট্যাপ করলে সংশ্লিষ্ট বিস্তারিত পেজে যাবে।

### ৯.২ গ্রাফসমূহ

**১. বিক্রয়ের ধারা (Line Chart)**
গত ৩০ দিন / ১২ মাস — টগল করা যাবে। দুটি রেখা: বিক্রয় ও আদায়। ফাঁকটাই বাকির পরিমাণ।

**২. মাসিক তুলনা (Grouped Bar Chart)**
এই মাস বনাম গত মাস বনাম গত বছরের একই মাস। চারটি সূচক: বিক্রয়, ক্রয়, খরচ, নিট লাভ।

**৩. মাসের লক্ষ্য পূরণ (Progress Ring)**
```
        ╭───────────╮
       │   ৭২%      │      লক্ষ্য: ৳৫,০০,০০০
       │  ৳৩,৬০,০০০ │      বাকি: ৳১,৪০,০০০
        ╰───────────╯      দিন বাকি: ৯
```
মাসের কত দিন গেছে তার তুলনায় এগিয়ে না পিছিয়ে — সবুজ বা লাল ইঙ্গিত। লক্ষ্য কোম্পানি, সেলসম্যান ও রুট — তিন স্তরে নির্ধারণ করা যাবে।

**৪. লাভের ধারা (Area Chart)**
মাস অনুযায়ী মোট লাভ (gross) ও নিট লাভ (net) পাশাপাশি। দুটির ফাঁক = পরিচালন খরচ।

**৫. সেরা ৫ পণ্য (Horizontal Bar)**
পরিমাণ বা টাকার অঙ্ক — টগল করা যাবে।

**৬. সেরা ৫ ক্রেতা (Horizontal Bar)**
সাথে প্রত্যেকের বর্তমান বাকি পাশে দেখাবে।

**৭. বাকির বয়স বিশ্লেষণ (Donut Chart)**
০-১৫ / ১৬-৩০ / ৩১-৬০ / ৬০+ দিন। ৬০+ অংশ লাল, ট্যাপ করলে সেই তালিকা।

**৮. খরচের বিভাজন (Donut Chart)**
ক্যাটাগরি অনুযায়ী — জ্বালানি, ভাড়া, বেতন, টোল ইত্যাদি। মাঝে মোট খরচ লেখা।

**৯. নগদ প্রবাহ (Stacked Bar)**
সপ্তাহ বা মাস অনুযায়ী — কত ঢুকলো (সবুজ), কত বের হলো (লাল)।

**১০. স্টকের মূল্যের ধারা (Line Chart)**
স্টকে আটকে থাকা টাকার পরিমাণ সময়ের সাথে বাড়ছে না কমছে।

### ১১.১ তিন স্তরের কাঠামো

দাম ও স্টক **সবসময় Variant স্তরে**।

### ১১.২ বহুস্তর ইউনিট

| পণ্য | Base unit | স্তর ১ | স্তর ২ |
|---|---|---|---|
| নুডলস | প্যাকেট | ১ কার্টন = ১২ প্যাকেট | — |
| চাল | কেজি | ১ বস্তা = ৫০ কেজি | — |
| চিপস | পিস | ১ প্যাক = ২০ পিস | ১ ব্যাগ = ৪ প্যাক |
| পানি ১ লিটার | বোতল | ১ কার্টন = ১২ বোতল | — |
| পানি ৫০০ মিলি | বোতল | ১ কার্টন = ২৪ বোতল | — |
| খোলা সয়াবিন | লিটার | ১ ড্রাম = ২০০ লিটার | — |

**নিয়মাবলি**
- স্টক সবসময় base unit-এ সংরক্ষিত
- প্রদর্শন বড় ইউনিটে: *"৩ ব্যাগ ১০ পিস (২৫০ পিস)"*
- **প্রতিটি স্তরের নিজস্ব দাম** — কার্টনের দাম কখনোই ১২ × প্যাকেটের দাম নয়
- অ্যাপ অন্য স্তরের দাম প্রস্তাব করবে (ধূসর), ইউজার বদলাতে পারবে
- `allow_decimal` — ওজনের পণ্যে দশমিক চালু
- Quantity কলাম `DECIMAL(14,3)`, কখনোই `INTEGER` নয়
- প্রতিটি স্তরের আলাদা বারকোড থাকতে পারে

### ১১.৩ CRUD নিয়ম

- **Add** — Category → Product → Variant → Units, ধাপে ধাপে; Excel দিয়ে একসাথে আমদানি
- **Edit** — দাম বদলালে `price_history`-তে রেকর্ড
- **Delete** — লেনদেন থাকলে শুধু `is_active = false`; না থাকলে স্থায়ী ডিলিট
- **ফ্রি স্কিম** — `free_qty` কলাম; "১০ + ১ ফ্রি" হলে স্টক কাটবে ১১, দাম নেবে ১০-এর

## ১২. পার্টি ব্যবস্থাপনা

`parties.type = supplier | customer` (ব্যবসার ধরন অনুযায়ী নাম বদলাবে)

**মূল তথ্য** — নাম (বাধ্যতামূলক), স্বয়ংক্রিয় কোড, ধরন, স্ট্যাটাস (active / inactive / closed)

**ব্যবসার মেয়াদ** — `business_start_date`, `business_end_date`। বন্ধ হলে নতুন ইনভয়েস হবে না, পুরনো লেজার ও আদায় চালু থাকবে।

**লোকেশন** — ঠিকানা, এলাকা, থানা, জেলা; "বর্তমান অবস্থান নিন" বাটনে GPS থেকে latitude/longitude (অফলাইনেও কাজ করে); ম্যাপে দেখতে `geo:` লিংকে ফোনের Maps অ্যাপ খুলবে; রুট ট্যাগ

**যোগাযোগ (সবই ঐচ্ছিক)** — প্রধান ও বিকল্প মোবাইল, WhatsApp, যোগাযোগকারীর নাম ও পদবি, ইমেইল, NID/ট্রেড লাইসেন্স, নোট। নম্বরে ট্যাপে কল, WhatsApp আইকনে লেজার PDF শেয়ার।

**আর্থিক** — `opening_balance`, `credit_limit` (অতিক্রম করলে সতর্কতা), পেমেন্টের শর্ত (৭/১৫/৩০ দিন)

**Nikash সংযোগ** — পার্টি যদি Nikash ব্যবহারকারী হয়, তার `NK-ID` যুক্ত করা যাবে

## ১৩. ক্রয় ও বিক্রয়

### ১৩.১ ক্রয়

**প্রবাহ:** সরবরাহকারী → পণ্য ও পরিমাণ (ইউনিটসহ) → ছাড় → পরিবহন খরচ → মোট → পরিশোধ → বাকি

Post করলে স্টক বাড়বে, সরবরাহকারীর লেজারে দেনা যোগ হবে, weighted average cost পুনঃগণনা হবে।

### ১৩.২ বিক্রয়

**প্রবাহ:** ক্রেতা → পণ্য ও পরিমাণ → ফ্রি স্কিম → ছাড় → মোট → নগদ আদায় → বাকি

- স্টক না থাকলে সতর্কতা (ব্লক নয়)
- credit limit ছাড়ালে সতর্কতা
- Post করলে স্টক কমবে, লেজারে পাওনা যোগ হবে, COGS রেকর্ড হবে
- ইনভয়েস PDF ও থার্মাল প্রিন্ট (৫৮ মিমি)
- সংযুক্ত ক্রেতা হলে তার অ্যাপে চালান পাঠানোর অপশন

### ১৩.৩ সাধারণ নিয়ম

**Draft → Post → Locked।** Post-এর পর সম্পাদনা করলে reverse entry হবে, সরাসরি বদলাবে না। রিটার্ন (ক্রয় ও বিক্রয় দুই দিকেই) আলাদা নথি হিসেবে থাকবে — মুদি ব্যবসায় ড্যামেজ ও মেয়াদোত্তীর্ণ রিটার্ন অপরিহার্য।

## ১৪. ইনভেন্টরি সিস্টেম

### ১৪.১ মূল নীতি

**স্টক কখনো সরাসরি update হবে না।** প্রতিটি পরিবর্তন `stock_movements`-এ নতুন সারি। বর্তমান স্টক = লেজারের যোগফল।

`movement_type`: purchase_in, sale_out, purchase_return, sale_return, damage, expiry, theft, adjustment, transfer_in, transfer_out, opening

### ১৪.২ ইনভেন্টরি ড্যাশবোর্ড

মোট স্টকের মূল্য (ক্রয় ও বিক্রয়মূল্যে), মোট আইটেম, কম স্টক, স্টক শেষ, মেয়াদ কাছে, অচল স্টক।

### ১৪.৩ স্টক তালিকা ও বিস্তারিত

ফিল্টার (ক্যাটাগরি, গুদাম, স্ট্যাটাস), সার্চ, বারকোড স্ক্যান।

প্রতিটি variant-এর পেজে: সব ইউনিটে পরিমাণ, গড় ও সর্বশেষ ক্রয়মূল্য, মোট মূল্য, গুদামভিত্তিক ভাগ, **সম্পূর্ণ নড়াচড়ার ইতিহাস**, গত ৩০ দিনের বিক্রির গ্রাফ।

### ১৪.৪ স্টক সমন্বয়

কারণ বাধ্যতামূলক (damage / expiry / theft / count_error / other), মন্তব্য ও ছবি, শুধু Admin ও Manager, বড় অঙ্কে Admin অনুমোদন, `audit_logs`-এ রেকর্ড, ক্ষতির মূল্য স্বয়ংক্রিয়ভাবে খরচে যোগ।

### ১৪.৫ ফিজিক্যাল স্টক গণনা

গণনা শুরু → count sheet → আসল পরিমাণ এন্ট্রি (অফলাইন ও বারকোডসহ) → সিস্টেম বনাম আসল তুলনা → Admin অনুমোদন → স্বয়ংক্রিয় adjustment → মোট ঘাটতি/উদ্বৃত্তের রিপোর্ট। গণনা চলাকালে ঐ গুদামে লেনদেন সাময়িক বন্ধ রাখার অপশন।

### ১৪.৬ গুদাম স্থানান্তর

`transfer_out` → in_transit → `transfer_in`। গ্রহণ নিশ্চিত করলে সম্পূর্ণ।

### ১৪.৭ ব্যাচ ও মেয়াদ (ঐচ্ছিক)

`track_expiry` চালু থাকলে ক্রয়ে ব্যাচ নম্বর ও মেয়াদ চাইবে, বিক্রয়ে FEFO অনুযায়ী প্রস্তাব দেবে।

### ১৪.৮ ইনভেন্টরি রিপোর্ট

বর্তমান স্টক, স্টক মূল্যায়ন, স্টক নড়াচড়া, কম স্টক ও পুনঃক্রয় প্রস্তাব, অচল স্টক, ক্ষতি ও মেয়াদ রেজিস্টার, দ্রুত বিক্রিত পণ্য, গণনার ইতিহাস।

## ১৬. খরচ ও গাড়ি

### ১৬.১ পূর্বনির্ধারিত ক্যাটাগরি

জ্বালানি, টোল, রোড কস্ট, গাড়ি মেরামত, গুদাম ভাড়া, দোকান ভাড়া, মোবাইল বিল, বিদ্যুৎ, বেতন, ড্রাইভার ভাতা, লোডিং/আনলোডিং, অন্যান্য

**ধরন** — Direct (ট্রিপ/রুটের সাথে যুক্ত) ও Indirect (সাধারণ)

### ১৬.২ দ্রুত খরচ (Quick Expense)

দৈনিক টুকটাক খরচ — চা-নাস্তা, কুলির মজুরি, রিকশা ভাড়া, গ্লাভস কেনা — এসবের জন্য আগে ক্যাটাগরি বানাতে হবে না। ইউজার **নাম লিখে টাকার অঙ্ক দিলেই** সেটা ঐ দিনের খরচে যোগ হয়ে যাবে।

**এন্ট্রি ফর্ম (১০ সেকেন্ডে শেষ)**

### ১৬.৩ নামের পুনরাবৃত্তি ঠেকানো

খোলা টেক্সট বক্সের একটাই বিপদ — একই খরচ পাঁচ রকম বানানে লেখা হয় ("তেল", "Tel", "গাড়ির তেল", "fuel")। তখন খরচের রিপোর্ট অকেজো হয়ে যায়। তিন স্তরে এটা ঠেকানো হবে:

**১. স্বয়ংক্রিয় প্রস্তাব (Autocomplete)** — ইউজার টাইপ শুরু করলেই তার নিজের আগের ব্যবহৃত নামগুলো নিচে দেখাবে, সাথে কতবার ব্যবহার করেছে। দ্বিতীয়বার থেকে সে আর টাইপ করবে না, ট্যাপ করবে।

**২. ক্যাটাগরিতে পদোন্নতি** — কোনো নাম ৫ বার ব্যবহৃত হলে সিস্টেম প্রস্তাব দেবে:

> *"'কুলির মজুরি' আপনি ৮ বার ব্যবহার করেছেন। এটাকে স্থায়ী ক্যাটাগরি বানাবেন? তাহলে রিপোর্টে আলাদা করে দেখা যাবে।"*

এক ট্যাপে ক্যাটাগরি তৈরি হবে এবং **আগের সব এন্ট্রি স্বয়ংক্রিয়ভাবে সেই ক্যাটাগরিতে সরে যাবে**।

**৩. পুনর্বিন্যাস (Re-categorize)** — মালিক যেকোনো সময় "অন্যান্য" খরচের তালিকা খুলে একসাথে কয়েকটা বেছে নিয়ে সঠিক ক্যাটাগরিতে সরাতে পারবে।

### ১৬.৪ অনুমোদন প্রবাহ

| ভূমিকা | খরচ যোগ করতে পারবে | অনুমোদন লাগবে |
|---|---|---|
| Owner | ✓ | না |
| Manager | ✓ | নির্ধারিত সীমার উপরে |
| Accountant | ✓ | নির্ধারিত সীমার উপরে |
| Salesman | ✓ (শুধু নিজের ট্রিপের) | সবসময় |
| Cashier | ✓ (শুধু দোকানের) | সবসময় |
| Storekeeper | ✗ | — |

- সীমা সেটিংসে নির্ধারিত (ডিফল্ট ৳২,০০০)
- অনুমোদনের অপেক্ষায় থাকা খরচ আলাদা তালিকায় থাকবে, **অনুমোদনের আগে রিপোর্ট বা লাভের হিসাবে যোগ হবে না**
- মালিকের অ্যাপে ব্যাজ দেখাবে: *"৩টি খরচ অনুমোদনের অপেক্ষায়"*
- বাতিল করলে কারণ লিখতে হবে, এন্ট্রিদাতা নোটিফিকেশন পাবে

### ১৬.৫ নিয়মিত খরচ (Recurring)

দোকান ভাড়া, গুদাম ভাড়া, বেতন, মোবাইল বিল, ইন্টারনেট — এগুলো প্রতি মাসে একই। একবার সেট করলে প্রতি মাসের নির্ধারিত তারিখে **স্বয়ংক্রিয়ভাবে draft এন্ট্রি তৈরি হবে** এবং মালিককে মনে করিয়ে দেবে।

`recurring_expenses`: ক্যাটাগরি, নাম, টাকা, মাসের কত তারিখে, শুরু ও শেষের তারিখ, স্বয়ংক্রিয় তৈরি হবে কিনা

মালিক শুধু "নিশ্চিত করুন" চাপবে। অঙ্ক বদলালে (যেমন বিদ্যুৎ বিল) এন্ট্রি করার সময় বদলে নেবে।

- ফিল্টার: ক্যাটাগরি, কে এন্ট্রি দিয়েছে, পেমেন্টের মাধ্যম, অবস্থা
- নাম দিয়ে সার্চ
- যেকোনো সারিতে ট্যাপ করলে বিস্তারিত পেজ — রসিদের ছবি, নোট, সম্পাদনার ইতিহাস
- উপরে ক্যাটাগরিভিত্তিক ভাগ দেখার টগল:

```
১২ সেপ্টেম্বর — মোট ৳১,৮৫০  (গতকাল ৳১,২০০ ↑ ৫৪%)
├─ জ্বালানি        ৳  ৮০০
├─ রোড কস্ট        ৳  ৩০০
├─ টোল             ৳  ২০০
├─ কুলির মজুরি     ৳  ৩০০
└─ অন্যান্য (৩টি)  ৳  ২৫০
```

এই মোট অঙ্ক সরাসরি `daily_summaries.expense_total`-এ যাবে এবং নিট লাভ থেকে বাদ যাবে। আলাদা করে কিছু করতে হবে না।

### ১৬.৭ পুরনো তারিখে খরচ যোগ করা (Back-dated entry)

বাস্তবে খরচ তোলা প্রায়ই দু-এক দিন পিছিয়ে যায়। তাই তারিখের ঘরটি সবসময় **সম্পাদনাযোগ্য** থাকবে।

- ডিফল্ট আজকের তারিখ বসানো থাকবে
- ট্যাপ করলে ক্যালেন্ডার খুলবে, যেকোনো পুরনো তারিখ বাছা যাবে
- সংরক্ষণ করলে খরচটি **ঐ তারিখের হিসাবে** যাবে, আজকের হিসাবে নয়

**আজ ছাড়া অন্য তারিখ বাছলে যা ঘটবে**

| বিষয় | আচরণ |
|---|---|
| ফর্মে ইঙ্গিত | তারিখের ঘর হলুদ হয়ে যাবে, নিচে লেখা উঠবে *"৪ দিন আগের তারিখ"* |
| সংরক্ষণের পর Toast | *"৮ সেপ্টেম্বরের খরচে যোগ হয়েছে"* — যাতে ভুল তারিখ বাছলে সাথে সাথে ধরা পড়ে |
| তালিকায় চিহ্ন | ঐ সারিতে ছোট ব্যাজ *"পরে যোগ করা"* |
| অনুমোদন | ৭ দিনের বেশি পুরনো তারিখ হলে Owner-এর অনুমোদন লাগবে |
| রেকর্ড | `entry_date` (খরচের তারিখ) ও `created_at` (কখন লেখা হলো) দুটোই আলাদা সংরক্ষিত থাকবে |

**সীমা**

| তারিখ | অনুমতি |
|---|---|
| আজ ও গতকাল | সবাই (যার খরচ যোগ করার অধিকার আছে) |
| ২-৭ দিন আগে | Manager ও Owner |
| ৭ দিনের বেশি আগে | শুধু Owner |
| বন্ধ করা মাসের ভেতরে | কেউ না — আগে মাস খুলতে হবে |
| ভবিষ্যতের তারিখ | অনুমোদিত নয় (ভুল বাছাই ঠেকাতে) |

**হিসাবে প্রভাব**

পুরনো তারিখে খরচ যোগ করলে সিস্টেম নিজে থেকেই **ঐ দিন থেকে আজ পর্যন্ত সব দৈনিক সারসংক্ষেপ পুনরায় গণনা করবে** (`daily_summaries` recalculation)। ফলে ৮ তারিখের নিট লাভ, ঐ সপ্তাহের হিসাব ও মাসের মোট — সবই স্বয়ংক্রিয়ভাবে ঠিক হয়ে যাবে। ইউজারকে কিছু করতে হবে না।

মাসিক সারসংক্ষেপ ইতিমধ্যে তৈরি হয়ে থাকলে সেটিও নতুন করে তৈরি হবে, আর মালিক নোটিফিকেশন পাবে: *"আগস্ট মাসের হিসাব হালনাগাদ হয়েছে"*।

একই নিয়ম **ক্রয়, বিক্রয় ও পেমেন্টের** ক্ষেত্রেও প্রযোজ্য — সব লেনদেনেই তারিখ পিছিয়ে দেওয়া যাবে, একই সীমা ও একই পুনঃগণনা কাজ করবে।

### ১৬.৮ সম্পাদনা, মুছে ফেলা ও ভুল সংশোধন

ভুল অঙ্ক বা ভুল এন্ট্রি প্রতিদিনই হয়, তাই সংশোধন সহজ রাখতে হবে — কিন্তু টাকার হিসাব বলে কোনো পরিবর্তন যেন নিঃশব্দে না ঘটে।

**সম্পাদনা (Edit)**

| অবস্থা | কে বদলাতে পারবে |
|---|---|
| একই দিনে, অনুমোদনের আগে | যে এন্ট্রি দিয়েছে + Manager + Owner |
| অনুমোদনের পর | শুধু Owner |
| আগের দিনের এন্ট্রি | শুধু Owner |
| মাস বন্ধ করে দেওয়ার পর | কেউ না (আগে মাস খুলতে হবে) |

খরচ সম্পাদনা করা তুলনামূলক নিরাপদ, কারণ এটা স্টক বা কারও লেজারে প্রভাব ফেলে না — শুধু নগদ ও লাভের হিসাব বদলায়। তাই সরাসরি বদলানো যাবে, reverse entry লাগবে না।

তবে **প্রতিটি পরিবর্তন রেকর্ড হবে**। বিস্তারিত পেজের নিচে দেখাবে:

```
সম্পাদনার ইতিহাস
৳৩০০ → ৳৪০০   করিম   ১২ সেপ্টে, ৩:৪০ PM
নাম বদল        করিম   ১২ সেপ্টে, ৩:৪১ PM
```

**মুছে ফেলা (Delete)**

- বাটনে লেখা থাকবে **"মুছুন"** — ইউজারের কাছে এটা সাধারণ ডিলিটের মতোই লাগবে
- ভেতরে soft delete হবে (`status = void`), রেকর্ড থেকে যাবে
- মুছে ফেলার সাথে সাথেই সব রিপোর্ট, ড্যাশবোর্ড ও লাভের হিসাব থেকে বাদ পড়বে
- ৳১,০০০-এর বেশি হলে কারণ লিখতে বলবে
- Toast-এ ৫ সেকেন্ডের জন্য **"পূর্বাবস্থায় ফিরুন"** বাটন থাকবে — ভুল করে মুছলে সাথে সাথে ফেরানো যাবে

**ট্রash (মুছে ফেলা তালিকা)**

মুছে ফেলা খরচগুলো ৩০ দিন একটা আলাদা তালিকায় থাকবে, শুধু Owner দেখবে। সেখান থেকে ফিরিয়ে আনা যাবে। ৩০ দিন পর তালিকা থেকে সরে যাবে কিন্তু ডেটাবেসে ও অডিট লগে থেকে যাবে।

**কেন স্থায়ী ডিলিট নয়** — কেউ যদি ৳৫০,০০০-এর একটা খরচ মুছে দেয়, লাভের রিপোর্ট নিঃশব্দে বদলে যাবে আর কেউ কোনোদিন জানবে না। soft delete-এ ইউজারের অভিজ্ঞতা একই থাকে, কিন্তু মালিক চাইলে সবসময় দেখতে পারে কী মুছেছে।

**অফলাইনেও** সম্পাদনা ও মুছে ফেলা কাজ করবে, sync হলে সার্ভারে যাবে।

### ১৬.৯ অন্যান্য নিয়ম

- খরচ এন্ট্রি **অফলাইনেও কাজ করবে**, sync হলে সার্ভারে যাবে
- রসিদের ছবি অফলাইনে ফোনে থাকবে, ইন্টারনেট এলে আপলোড হবে
- প্রতিটি খরচে `created_by` থাকবে, তাই কে কত খরচ দেখাচ্ছে তার রিপোর্ট বের হবে
- স্টক ক্ষতি ও মেয়াদোত্তীর্ণ পণ্যের মূল্য স্বয়ংক্রিয়ভাবে খরচ হিসেবে যোগ হবে
- মাস বন্ধ (month close) করার সুবিধা থাকবে — একবার বন্ধ করলে ঐ মাসের হিসাব আর বদলাবে না

### ১৬.১০ গাড়ি ও ট্রিপ

মূলত Warehouse-এর জন্য। `vehicles`: reg_no, ধরন, ড্রাইভারের নাম ও ফোন। `vehicle_trips`: তারিখ, রুট, start_km, end_km, জ্বালানি, টোল, ড্রাইভার ভাতা → **প্রতি ট্রিপের মোট খরচ ও রুটভিত্তিক লাভ**।

ট্রিপের সাথে যুক্ত খরচ Direct হিসেবে গণ্য হবে, তাই কোন রুট আসলে লাভ দিচ্ছে সেটা আলাদা করে বের হবে।

| রিপোর্ট | বিবরণ |
|---|---|
| বিক্রয় | দিন/সপ্তাহ/মাস/custom; পার্টি, পণ্য, কর্মী ভিত্তিক |

| **লাভ-ক্ষতি** | Gross, Net, মার্জিন |
| স্টক | বর্তমান, মূল্যায়ন, কম স্টক, অচল, মেয়াদ |
| ক্যাশ বই | দৈনিক নগদ আয়-ব্যয় |
| পার্টি লেজার | পূর্ণ হিসাব |

**লাভের সূত্র**
```
COGS         = Weighted Average Cost
Gross Profit = বিক্রয় − COGS
Net Profit   = Gross Profit − (Direct + Indirect খরচ)
```

সব রিপোর্টে date-range ফিল্টার + PDF ও Excel এক্সপোর্ট।

## ১৮. অফলাইন ও Sync

**প্রবাহ:** এন্ট্রি → লোকাল SQLite (তাৎক্ষণিক) → sync queue → ইন্টারনেট এলে সার্ভারে → synced

প্রতিটি রেকর্ডে `uuid` (ফোনে তৈরি), `sync_status`, `updated_at`, `device_id`। সার্ভার `uuid` দেখে ডুপ্লিকেট ঠেকাবে।

**Sync চালু হবে:** অ্যাপ খুললে, ইন্টারনেট ফিরলে, প্রতি ৫ মিনিটে, প্রতিটি এন্ট্রির পর

**ডেটা হারানো প্রতিরোধ — ছয়টি নিয়ম**
1. Logout-এ লোকাল ডেটাবেস মুছবে না, শুধু token মুছবে
2. Pending ডেটা থাকলে logout আটকাবে (force logout-এ আলাদা কনফার্মেশন)
3. অফলাইনে অটো-logout হবে না
4. হেডারে সবসময় sync ব্যাজ
5. ২ দিনের বেশি sync না হলে স্থায়ী হলুদ বার + দৈনিক নোটিফিকেশন
6. দৈনিক লোকাল ব্যাকআপ ফাইল, শেয়ারযোগ্য

**Conflict:** append-only নীতি — সম্পাদনার বদলে reverse entry
**লোকাল স্টোরেজ:** ফোনে শেষ ৯০ দিন, সার্ভারে সব

## ২২. সাবস্ক্রিপশন

**অবস্থাচক্র:** `trial → active → grace → readonly → blocked`

| অবস্থা | সময় | অ্যাপে কী হবে |
|---|---|---|
| trial | ১৫ দিন | সম্পূর্ণ অ্যাক্সেস |
| active | প্যাকেজ অনুযায়ী | সম্পূর্ণ অ্যাক্সেস |
| grace | ৩ দিন | সম্পূর্ণ + লাল ব্যানার |
| readonly | grace-এর পর | দেখা যাবে, নতুন এন্ট্রি নয় |
| blocked | ৬০ দিন পর | লগইন বন্ধ, ডেটা ১২ মাস সংরক্ষিত |
| lifetime | — | সবসময় সক্রিয়, ফ্রি |

**গুরুত্বপূর্ণ নিয়ম**
- সাবস্ক্রিপশন **কোম্পানির নামে**, ইউজারের নামে নয়
- মেয়াদ চেক হবে **প্রতিটি API রিকোয়েস্টে**, শুধু লগইনে নয়
- তারিখ **সার্ভারের timestamp** দিয়ে, ফোনের ঘড়ি দিয়ে নয়
- `last_verified_at` — ৭ দিন sync না হলে অ্যাপ লক
- `max_devices` — সর্বোচ্চ ৩ ডিভাইস
- `max_users` — প্যাকেজ অনুযায়ী


**সব টেবিলে:** `created_at`, `updated_at`, `is_archived`
**লেনদেনের টেবিলে:** `uuid`, `sync_status`, `device_id`
**RLS:** প্রতিটি কোম্পানি-স্তরের টেবিলে `company_id` ভিত্তিক Row Level Security বাধ্যতামূলক
**ইনডেক্স:** `(company_id, date)`, `(company_id, party_id)`, `(company_id, variant_id)`, `uuid` — সবগুলোতে

# ভাগ ৭ — বিতরণ ও পরিকল্পনা

## ২৬. বিতরণ ও আপডেট

```
nikash.vercel.app            → পরিচিতি
nikash.vercel.app/download   → APK ডাউনলোড (এই লিংক শেয়ার করবেন)
nikash.vercel.app/admin      → কন্ট্রোল প্যানেল
```

**ডাউনলোড পেজে:** লোগো, বড় ডাউনলোড বাটন (ভার্সনসহ), ফাইলের আকার, ছবিসহ ইনস্টল নির্দেশনা (Play Protect সতর্কতা আলাদা করে ব্যাখ্যা), QR কোড, যোগাযোগের নম্বর

**গুরুত্বপূর্ণ:** WhatsApp/Messenger-এ সরাসরি `.apk` লিংক নয়, **পেজের লিংক** শেয়ার করবেন। APK থাকবে GitHub Releases-এ।

**আপডেট:** JS পরিবর্তনে EAS Update (OTA, স্বয়ংক্রিয়); native পরিবর্তনে নতুন APK — অ্যাপ `/api/app-version` চেক করে পপআপ দেখাবে; `force_update` ফ্ল্যাগে পুরনো ভার্সন ব্লক।
