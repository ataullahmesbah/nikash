# নিকাশ ওয়েব (অ্যাডমিন প্যানেল + পাবলিক সাইট) — PRD v2

স্ট্যাক: Next.js 16 (App Router, Turbopack) · Tailwind v4 · Supabase · recharts

---

## ১. দুটি আলাদা অংশ

| অংশ | রুট | কে দেখে | অথ |
|---|---|---|---|
| পাবলিক সাইট | `/`, `/services`, `/pricing`, `/download`, `/about`, `/contact`, আইনি পেজ | যে কেউ | নেই |
| অ্যাডমিন প্যানেল | `/admin/**` | আমরা (প্ল্যাটফর্ম অ্যাডমিন) | `platform_admins` + bcrypt + JWT কুকি + ঐচ্ছিক 2FA |

> অ্যাডমিনরা Supabase Auth ব্যবহার করে **না** — আলাদা টেবিল ও সেশন, যাতে
> কোম্পানির ইউজারদের সাথে কোনোভাবেই মিশে না যায়।

## ২. v2-তে যা যোগ/বদল হয়েছে

### ২.১ ড্যাশবোর্ড (`/admin`)
- গ্রাফ: কোম্পানি বৃদ্ধি (এরিয়া), মাসিক আদায় (বার), ব্যবসার ধরন (ডোনাট)
- সংখ্যা: মোট/সক্রিয়/ট্রায়াল/ব্লক কোম্পানি, বকেয়া, MRR, যাচাই বাকি
- তালিকা: নতুন কোম্পানি, শীঘ্রই মেয়াদ শেষ, সাম্প্রতিক কার্যক্রম
- সব সংখ্যা এক RPC-তে — `admin_dashboard_stats()` (service_role only)

### ২.২ নোটিফিকেশন (নতুন)
- টেবিল `notifications` — `audience` = `company` | `platform`
- ট্রিগার থেকে নিজে থেকেই তৈরি হয়:
  - নতুন কোম্পানি সাইনআপ → আমাদের
  - পেমেন্ট রিকোয়েস্ট এল → আমাদের
  - পেমেন্ট অনুমোদন/বাতিল → কোম্পানিকে
  - কোম্পানির স্ট্যাটাস/মেয়াদ বদল → কোম্পানিকে
  - নোটিশ পোস্ট → লক্ষ্য কোম্পানিগুলোকে ফ্যান-আউট
- **ঘণ্টা আইকন** (নেভে) — প্রতি ১৫ সেকেন্ডে পোল, লাল ব্যাজ, পড়া-চিহ্ন
- **পূর্ণ পেজ** `/admin/notifications`
- 🔒 `audience='platform'` সারির কোনো `authenticated` RLS পলিসি নেই — শুধু
  সার্ভারের service_role পড়তে পারে, তাই কোম্পানির ইউজার আমাদের বার্তা দেখে না

### ২.৩ ব্যবহারকারী ও রোল (`/admin/users`)
- অ্যাডমিন তৈরি/সম্পাদনা/নিষ্ক্রিয়, রোল বদল
- 🔒 শেষ সক্রিয় super_admin-কে নামানো/নিষ্ক্রিয় করা যায় না (লকআউট ঠেকাতে)
- DELETE আসলে নিষ্ক্রিয় করে — অডিট লগের রেফারেন্স ভাঙে না
- সব কাজ `admin_logs`-এ

### ২.৪ নোটিশ টার্গেটিং (`/admin/notices`)
- চার মোড: **সবাই** · **ব্যবসার ধরন** · **নির্দিষ্ট কোম্পানি (চেকবক্স)** · **স্ট্যাটাস**
- `notices.target_company_ids uuid[]`, `target_statuses text[]`
- ফর্মে লাইভ "কতজন দেখবে" হিসাব
- RLS পলিসি নতুন করে লেখা — কোম্পানি শুধু তার জন্য লেখা নোটিশই পায়

### ২.৫ কোম্পানি (`/admin/companies`, `/admin/companies/[id]`)
- তালিকায় খোঁজা (নাম/Nikash ID/ফোন), স্ট্যাটাস ও ধরন ফিল্টার, "শীঘ্রই মেয়াদ শেষ"
- ডিটেইলে **SubscriptionPanel**: বাড়ানো / **কমানো** / নির্দিষ্ট তারিখ —
  দ্রুত চিপ (৭/১৫/৩০/৯০/৩৬৫), লাইভ প্রিভিউ, **কারণ বাধ্যতামূলক**
- **StatusPanel**: রেডিও কার্ড + ব্যাখ্যা, ব্লক/readonly-তে কারণ লাগে
- `set_subscription_end()` RPC — service_role only, কমানোও সমর্থন করে

### ২.৬ পেমেন্ট (`/admin/payments`)
- ট্যাব: যাচাই বাকি · সব পেমেন্ট · ইনভয়েস
- **ম্যানুয়াল পেমেন্ট** — কোম্পানি খুঁজে, প্ল্যান বাছলে দাম/দিন নিজে বসে,
  ইনভয়েস (NK-INV-YYYY-0001) তৈরি + মেয়াদ বৃদ্ধি + রেকর্ড — এক ট্রানজ্যাকশনে
- 🔒 একই TrxID দুইবার তোলা আটকায়

### ২.৭ ফিনান্স (`/admin/finance`) — নতুন
- মাসভিত্তিক আদায় (বার), মাধ্যম অনুযায়ী (ডোনাট)
- এই মাস vs গত মাস, মাসিক গড়, যাচাই বাকি, **সম্ভাব্য রিনিউ (৩০ দিন)**
- মেয়াদ শেষ হতে যাওয়া কোম্পানি ও অপরিশোধিত ইনভয়েস

### ২.৮ সেটিংস (`/admin/settings`) — ৬ ট্যাব
প্রোফাইল ও 2FA · প্ল্যান ও দাম · পেমেন্ট নম্বর · সাপোর্ট তথ্য · অ্যাপ লিংক · বিলিং নিয়ম
- সবই `platform_settings` (key → jsonb); **শুধু জানা key লেখা যায়** (হোয়াইটলিস্ট)
- `public.%` key অ্যাপ পড়তে পারে, বাকিগুলো নয়
- লেখার অধিকার শুধু super_admin-এর
- পাসওয়ার্ড বদলাতে **বর্তমান পাসওয়ার্ড লাগে** (কুকি চুরি হলেও দখল ঠেকাতে)

### ২.৯ যোগাযোগ বার্তা (`/admin/contacts`) — নতুন
ওয়েবসাইটের ফর্ম থেকে আসা বার্তা, স্ট্যাটাস বদল (নতুন/পড়া/উত্তর দেওয়া/বন্ধ)

## ৩. পাবলিক সাইট

| পেজ | কী আছে |
|---|---|
| `/` | হিরো + ফোন মকআপ · সংখ্যা · সমস্যা→সমাধান · তিন স্তর · ৯টি ফিচার · ৩ ধাপ · অফলাইন · দামের ঝলক · FAQ · শেষ CTA |
| `/services` | ৬টি মডিউল + অ্যাপের বাইরের ৪টি সেবা |
| `/pricing` | লাইভ প্ল্যান তালিকা, "সব প্ল্যানে যা থাকে", পেমেন্ট নম্বর |
| `/download` | **QR কোড** (সার্ভারেই তৈরি), ইনস্টল গাইড, প্রয়োজনীয়তা, প্রথম দিনের কাজ, ভার্সন ইতিহাস, সাপোর্ট |
| `/about` | কেন বানানো, নীতি, সময়রেখা |
| `/contact` | ফোন/হোয়াটসঅ্যাপ/ইমেইল কার্ড + ফর্ম |
| `/privacy`, `/terms`, `/refund` | আইনি |

- সাপোর্ট নম্বর, পেমেন্ট নম্বর, APK লিংক — কোথাও হার্ডকোড নেই, সব
  `platform_settings` থেকে (`lib/public-settings.ts`)
- সেটিংস পড়া ব্যর্থ হলেও পেজ ভাঙে না (fallback)

## ৪. নিরাপত্তার সারসংক্ষেপ

| ঝুঁকি | প্রতিরোধ |
|---|---|
| কোম্পানির ইউজার আমাদের নোটিফিকেশন পড়ে ফেলা | `platform` audience-এ কোনো authenticated পলিসি নেই |
| ভুয়া নোটিফিকেশন বানানো | `notify()` শুধু service_role (ট্রিগার SECURITY DEFINER বলে ভেতর থেকে চলে) |
| বিক্রয়কর্মী পোস্ট করা বিল আনপোস্ট/ডিলিট করা | DB ফাংশনে `has_role(['owner','manager'])` |
| অন্য কোম্পানির সারিতে হাত দেওয়া | প্রতিটি SECURITY DEFINER ফাংশনে `current_company_id()` মিল |
| সেটিংসে যা খুশি key ঢোকানো | API-তে key হোয়াইটলিস্ট + টাইপ/দৈর্ঘ্য যাচাই |
| সেশন কুকি চুরি করে পাসওয়ার্ড বদল | বর্তমান পাসওয়ার্ড বাধ্যতামূলক |
| শেষ super_admin হারানো | নামানো/নিষ্ক্রিয় করা ব্লকড |
| যোগাযোগ ফর্মে স্প্যাম | হানিপট + IP রেট লিমিট (১০ মিনিটে ৩) + কড়া যাচাই |
| ইনভয়েস/PDF-এ HTML ইনজেকশন | সব ডাইনামিক লেখা `esc()` দিয়ে |
| ডাবল পেমেন্ট এন্ট্রি | TrxID ইউনিক চেক |
| অ্যাডমিন RPC যে কেউ ডাকা | `revoke execute ... from public, anon, authenticated` |
